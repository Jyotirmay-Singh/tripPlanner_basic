## Receipt and sharing behavior

Attach image opens the system gallery directly. Android 7–12 uses **Save to folder**; Android
13+ uses **Save to gallery**. Camera, microphone, external-storage read/write and all broad
media-read permissions remain excluded. No camera/source-selection sheet was restored.

The existing app invitation and group-code messages already use the stable APK URL. Its
verified destination now points to this build, so previously shared messages reach the new
APK. The matching source redirect is recorded in frontend/vercel.json. Only the project-level
Android download route was published; the production website was not rebuilt or redeployed.
Automatic branch-preview deployments may exist.

Private logs, exact provider metadata and verification receipts are retained under
`.release-tmp/android-release-20261120/`. The consolidated local handoff includes this
report and the updated message; credentials remain private.

## Recovery and remaining acceptance

- Keep the existing app installed and preserve pending local entries. Do not clear storage or
  uninstall to work around an update/signing error. Build 28 retains the normal production
  package and direct-APK signer; the separate QA package is not replaced.
- If installation is blocked, retain the exact Android error and package/version details,
  verify the download checksum and free space, and resolve the specific error. A version
  downgrade is not a safe general recovery method; use a reviewed forward build if required.
- If the new public download needs withdrawal, restore the recorded previous Vercel routing
  version `9b504eb1-6ca9-4c4c-9ded-db3e3a42b9dc` only after verifying it still preserves every
  unrelated route. The backed-up Android destination is the build-24 GitHub asset. Update
  `frontend/vercel.json` to match, verify the complete anonymous download, homepage and QA
  route, and record the rollback. Do not redeploy the backend to roll back a download link.
- The existing free Render service can cold-start. Check `/api/health` before investigating
  client behavior; restart only the identified existing service using its operating runbook.
  This release creates no hosting resource, synthetic fixture, account or storage migration.
- Future device acceptance must cover upgrade with retained pending data, password/Google
  sign-in, groups, direct gallery select/cancel/crop/upload/view, Android 7–12 folder saving
  and Android 13+ gallery saving, offline recovery, notifications and external UPI handoff.
  Provider setup and available Android devices remain prerequisites; no real transfer is
  authorized. Community safety/mandatory review belongs to the separate coordinated release.
